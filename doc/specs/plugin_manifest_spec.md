# プラグインマニフェスト仕様

本書は、`plugin_manifest.json` の公開仕様を定義する。

## 基本

各プラグインは、自身のルートディレクトリに `plugin_manifest.json` を置く。

最低限必要なキーは次のとおり。

- `id`
- `name`
- `version`
- `entry_point`

例:

```json
{
    "id": "hoi4",
    "name": "Hearts of Iron IV",
    "version": "1.14.*",
    "entry_point": "hoi4.py"
}
```

## キー

### `id`

プラグインを一意に識別する文字列。

### `name`

表示名。

### `version`

人間向けのバージョン表記。

### `entry_point`

プラグインの実体を指す相対パス。

例:

- `hoi4.py`
- `hoi4.exe`
- `hoi4.dll`

### `entry_kind`

任意。`entry_point` の種類を明示する文字列。

省略時は `entry_point` の拡張子から推定する。

想定値:

- `python`
- `executable`
- `native`
- `source`

## 実行モデル

マニフェストは、プラグイン実体の配置形式を表す。

ただし、配置形式と実行方法は同義ではない。

現時点の整理は次のとおり。

- `.py`
  現行ローダが直接ロードできる
- `.exe`
  実行形式のプラグイン実体として扱えるが、呼び出しホストは別途必要
- `.dll` / `.pyd` / `.so` / `.dylib`
  native 実体として扱えるが、呼び出しホストは別途必要
- `.c`
  ソースコードであり、直接ロード対象にはしない

`.c` は公開仕様上「プラグイン実体そのもの」ではなく、「native 実体を生成するためのソース」として扱う。

## 方針

本体は、プラグインの実体形式に依存してもよいが、形式ごとの読み込み手順はローダ内部へ閉じ込める。

本体の他の箇所は、原則として次だけを見る。

- `Plugin`
- 公開API
- 公開フック
- 公開仕様

`plugin.module` のようなローダ都合の内部表現は、ローダ外へ広げない。
